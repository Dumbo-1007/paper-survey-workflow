# 标签词表（闭集）

三轴标签是本套归档范式能「一键找出同类论文」的前提。**只允许从下面的清单里选词**，
不在清单里的词先补进本文件再用，否则同一个概念会长出几种写法（`多模态融合` / `多模态` / `跨模态融合`），
标签就废了。

> [!warning] 这套词表是针对**医学影像 / 脑疾病分析**方向的示例词表。
> 换方向时只需替换本文件的三份清单，其余流程（卡片结构、脚本、Dataview）完全不变。

## 怎么选：三轴各管一件事

| 轴 | 回答的问题 | 判定方法 | 数量 |
| --- | --- | --- | --- |
| `种类/…` | 论文解决**哪类任务**？ | 只看标题/摘要就能定；它决定这篇论文属于哪个赛道 | 1 个（跨任务最多 2 个） |
| `挑战/…` | 这类任务的**核心难点**是什么，本文主攻哪个？ | 看 intro 里作者列的 gap、看方法章节为谁设计 | 2~3 个 |
| `技术/…` | 本文**实际用了什么技术**？ | 看方法章节用了哪些模块/损失/训练策略 | 1~4 个 |

**示例**：「SAM 免训练证据提示」这篇 →
`种类/医学图像分割`（做的是分割任务）· `挑战/通用基础模型与上下文学习` + `挑战/不确定性建模`（攻的是大模型适配与过度自信两个难点）· `技术/提示学习与上下文学习` + `技术/不确定性建模`（用的是提示生成与证据学习）。

符号看着重复（`不确定性建模` 同时出现在挑战轴和技术轴）是正常的：
挑战轴说的是「这是个难点」，技术轴说的是「用不确定性建模这个工具去解」。两轴合起来用 Dataview 才能问出
「所有用不确定性建模解决半监督问题的论文」。

## 一、种类（任务维度）

| 标签 | 判定要点 |
| --- | --- |
| `种类/疾病诊断与分型` | 输入影像/信号，输出诊断类别或亚型 |
| `种类/疾病风险与转化预测` | 输出的是未来是否发病/是否转化，含生成未来影像做预测的工作 |
| `种类/医学图像分割` | 输出像素/体素级掩码 |
| `种类/影像配准与纵向分析` | 输出的是空间变换或跨时间点对齐/演化建模 |
| `种类/脑网络与影像表征分析` | 重点是表征本身（如结构-功能耦合关系），不直接落到某个诊断任务 |
| `种类/多任务与基础模型` | 一个模型同时做多个任务，或定位为可迁移的基础模型 |

## 二、挑战（方法维度）

| 标签 | 判定要点 |
| --- | --- |
| `挑战/多模态融合` | 多模态信息如何对齐、互补、加权 |
| `挑战/高阶关系建模` | 需要建模成对以上的关系（超图、高阶交互），而不只是两两相关 |
| `挑战/时序与动态建模` | 时间维度、动态图、状态演化 |
| `挑战/半监督学习` | 少量标注 + 大量无标注 |
| `挑战/少标注与小样本` | 标注量极少（few-shot / zero-shot / 单参考），无标注数据也不多 |
| `挑战/缺失模态与缺失视图` | 推理时部分模态/视图不可得 |
| `挑战/可解释性与证据推理` | 要求模型给出可追溯的依据，而非只给分数 |
| `挑战/知识注入与LLM驱动` | 把外部知识、文本、大模型能力引入视觉/影像任务 |
| `挑战/不确定性建模` | 模型需要表达「有多不确定」，而不是只给点估计 |
| `挑战/生成式建模与未来预测` | 需要生成中间产物（未来影像、缺失数据）来辅助预测 |
| `挑战/通用基础模型与上下文学习` | 把大模型迁到本领域、上下文学习范式适配 |
| `挑战/难样本与类别不平衡` | 难例挖掘、长尾分布、少数类性能 |
| `挑战/多任务协同` | 多任务之间互相干扰或互相对齐 |
| `挑战/结构-功能耦合` | 跨模态结构性关联本身是研究问题 |

## 三、技术（技术维度）

| 标签 | 判定要点 |

## 维护规则

1. 新标签必须**先加进本文件**，再进元数据表。词表是唯一来源。
2. 命名用「中文短语」，不用缩写（写 `大语言模型与知识注入`，不写 `LLM`），保证在标签面板里可读。
3. 每个标签**至少 2 篇**才值得存在。只出现一次的词，先想一想它能不能并进已有标签。
4. 改标签名时，直接改元数据表并重跑归档脚本——卡片 frontmatter 由脚本重建，不要一篇篇手改。
