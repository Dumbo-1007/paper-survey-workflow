# 完整工作流

## 一、这套流程解决什么问题

单次读完一篇论文，收获是「当时懂了」；做完 N 次汇报后，痛点是：

| 痛点 | 后果 | 本流程的解法 |
| --- | --- | --- |
| 读完就忘，几个月后只剩一个标题 | 无法复用，等于白读 | 卡片保留「研究问题 + 方法要点 + 自评」，半年后 3 分钟回忆全文 |
| 每次汇报格式重来一遍 | 时间浪费在排版上 | LaTeX 模板固定 8 节，只填内容 |
| 读了很多篇，说不出领域全貌 | 汇报时讲不出「别人做到哪了」 | 三轴标签 + 分类表，把论文变成可检索的结构 |
| 找不到同类论文做对比 | 无法判断自己的工作是否新颖 | Dataview 按标签自动聚出同类论文 |
| 灵光一现的改进想法丢了 | 开题时想不起来 | 自评一节强制写下「可改进方案」，公式级落地 |

## 二、五步循环

```
①选论文 ──► ②精读 ──► ③写报告(LaTeX) ──► ④归档(脚本) ──► ⑤复用(分类表/标签)
   ▲                                                        │
   └──────────────── 按分类表暴露的空白找下一篇 ◄───────────┘
```

| 步骤 | 产出 | 存放位置 | 文件 |
| --- | --- | --- | --- |
| ① 选论文 | 2 篇论文 PDF | `reports/<批次>-<序号>/论文原文.pdf` | 门槛表见下文第三节 |
| ② 精读 | 笔记、框架图截图 | 随手记，截图存 `reports/<批次>-<序号>/pic/` | — |
| ③ 写报告 | `document.tex` + 编译出的 `document.pdf` | `reports/<批次>-<序号>/` | `latex/document.tex` |
| ④ 归档 | 论文卡片 + 分类表 + 总索引 | Obsidian 库 | `tools/build_cards.py` |
| ⑤ 复用 | 检索、对比、找空白 | Obsidian 标签面板 / Dataview | `obsidian/` 下的模板 |

**关键设计**：③ 的报告是**唯一手写内容**，④ 的卡片全部由脚本从报告 + 元数据表生成。
报告改了 → 重跑脚本 → 卡片同步。永远不要手改卡片正文，否则下次重跑就覆盖了。

## 三、第一步：怎么选论文

每次调研固定 2 篇，理由：单篇没有对比就没有判断力；两篇能构成一组对照
（同一任务的两条技术路线，或同一方法在两个任务上的表现）。汇报时第三点「横向对比」自然成立。

### 质量门槛（示例，按自己方向改）

| 类型 | 门槛 | 说明 |
| --- | --- | --- |
| 期刊 | 中科院一区 / JCR Q1 | 记录影响因子，便于后续按影响力排序 |
| 会议 | CCF-A 或领域顶会 | 记录等级，如 CCF A |
| 例外 | 临床/领域顶刊（可放宽区划） | 允许少量例外，但在元数据「分区」里如实标注 |

选论文的三个优先顺序：

1. **顺着顶会顶刊的最新一届目录扫**，比关键词检索更能发现方法级的动向。
2. **顺着已读论文的 related work 往外扩**：一篇文章引的、以及引它的（逆向引文）往往最相关。
3. **优先选「有对比价值」的**：同一问题不同解法；同一方法不同任务；或一篇综述 + 一篇代表性工作。

### 元数据表：一开始就填

选好论文后**立刻**在 `tools/metadata.csv` 里加一行（用 `tools/metadata.example.csv` 的表头）。
只填标题、期刊、年份、分区这类**摘抄级信息**，标签栏先空着——标签在读完、写完自评之后再定，
那时候你才知道这篇真正攻的是哪个难点。

## 四、时间预算（以 2 篇/次 为例）

| 环节 | 时间 | 说明 |
| --- | --- | --- |
| 选题 + 下载 + 建目录 | 0.5 h | 顺手填元数据表的标量列 |
| 精读 1 篇（含截图、推公式） | 2~3 h | 边读边在模板里填「研究问题 / 动机」两节，读完即写完一半 |
| 写报告 1 篇 | 2~4 h | 方法要点占一半篇幅，自评占四分之一 |
| 编译 + 归档 + 定标签 | 0.5 h | 跑一次脚本 |
| 汇报 | 0.5 h | 提纲见 `obsidian/templates/调研批次索引模板.md` |

一篇的完整闭环约 5~8 小时。报告不要一次性写完：**读第一章时就动手填第一节**，读的过程就是写作的过程。

## 五、汇报时讲什么（4 点法）

1. **它解决什么问题**（研究对象 + 痛点）——用一句不含术语的话讲清
2. **它的核心思路**（一张框架图 + 3 分钟讲完的方法要点）
3. **为什么比之前好**（主实验对比 + 消融里贡献最大的模块）
4. **对我有什么用**（自评一节：能借用哪个模块、要改什么、我准备怎么改）

前三点考的是「读懂了没有」，第四点考的是「有没有想法」。汇报的加分项几乎都在第四点。

## 六、归档的时机与检查

报告 `document.pdf` 编译成功后就归档，不要攒。归档后过一遍这三条：

- [ ] 分类表里这篇出现在预期的位置（说明标签选对了）
- [ ] 卡片里的「同类论文」查出来的是真的同类（标签不是选得太泛）
- [ ] 卡片正文没有公式没渲染（`$…$` 里混了中文 → 见 `docs/05-LaTeX转Obsidian规范.md`）

## 七、长期复利：从「读」到「用」

- **找空白**：分类表的每一节末尾都是「这个方向只有 N 篇」的提示。出现 5 篇以上的标签是热点，
  只有 1~2 篇的标签可能是空白——也可能只是没人关心，要用自评里的「可改进方案」去判别。
- **建方法清单**：把多篇论文里反复出现的模块（一致性约束、原型对齐、证据融合……）单独抽成一页，
  这就是日后写方案的零件库。
- **反向写开题**：开题报告的结构 ≈ 分类表（别人做到哪）+ 自评集合（我能改什么）。
  归档做得好，开题就是把自己写过的东西重组一遍。
