# 阅读报告写作规范

报告用 LaTeX 写，模板见 `latex/document.tex`。本文件规定「每一节该写什么」，
以及一条硬约束：**节标题不能改名**——归档脚本靠节标题切分内容，标题一改，卡片就空了。

## 一、节的对应关系

| LaTeX 节标题 | 归档到卡片的小节 | 建议篇幅 |
| --- | --- | --- |
| `阅读文献来源` | 文献来源（引用块） | 1 行引用 + 1 张首页截图 |
| `论文待研究科学问题` | 研究问题 | 150~250 字，一段话 |
| `作者研究动机` | 研究动机 | 150~250 字 |
| `论文工作的主要内容` | 方法要点 | 全文 50%~60% |
| `实验数据与评估指标` | 实验结果与指标 | 150~300 字 |
| `实验结果` | 实验结果与指标 | 300~600 字 |
| `作者工作评价（优点、缺点、后续工作要点）` | 不入卡片，汇报时用 | 100~200 字 |
| `自己对该论文的评价（优点、缺点、可改进方案）` | 自评 | 200 字 + 公式 |

## 二、逐节写法

### 1. 阅读文献来源

一行完整引用：作者、题目、期刊/会议、卷期页、年份、DOI。再截一张论文首页图
（`pic/screenshot001`）。**第一行会被脚本抓成卡片的「文献来源」**，所以不要在这一节先写别的。

```latex
\section{阅读文献来源}
\noindent
A. Author, B. Author and C. Author, "Paper Title," in Journal Name, vol. 33, pp. 1-15, 2024, doi: 10.xxxx/xxxx.
```

### 2. 论文待研究科学问题

**只写问题与结论，不写背景综述。** 目标：半年后只看这一段就能回忆全文。推荐句式：

> 论文针对「<场景/对象>」在「<任务>」中的「<痛点>」，提出「<方法名>」……
> 作者采用「<关键技术 1>、<关键技术 2>」……在「<数据集列表>」上评估，
> 以「<设置>」为例，在「<数据集>」上「<指标>」达到「<数字>」，高于「<基线>」「<数字>」。

要素齐了就是合格：**痛点 → 方法 → 关键设计 → 数据集 → 数字**。

反例（不合格）：把 abstract 翻译一遍，只讲动机不讲结果；或者只讲结果不讲方法设计。

### 3. 作者研究动机

分三层写，每层一两句：

1. **现有方法不够在哪**：尽量写成可对照的 gap 列表（需要人工干预 / 依赖大量标注 / 假设太强 / 计算昂贵）。
2. **作者要解决什么**：把 gap 和作者的设计一一对应。
3. **期望收益**：效率、精度、可解释性、临床可用性分别是哪一条。

### 4. 论文工作的主要内容（报告主体）

建议顺序：

1. **一句话定位**：这篇文章属于哪条技术路线，核心手段是什么。
2. **整体框架**：插框架图，按模块逐个说清输入输出。图里的模块名要和正文一致。
3. `\subsection{基础知识铺垫}`：**读懂本文必须的前置概念**，用自己的话讲一遍
   （如对比学习中 InfoNCE 的作用、证据学习为什么要转成狄利克雷分布）。
   这一步不是抄 related work，而是「我为了读懂它补了什么」。
4. **关键公式**：见下一节。

> [!warning] 最常见的失分点
> 方法一节写成论文的目录复述（「本文提出了 A 模块和 B 模块」）而没有解释
> 「为什么需要 A」「A 和 B 谁在起作用」。**每个模块后面都要跟一句「为了解决什么」**。

### 5. 公式与符号规范

**每个关键公式后面必须写符号含义与设计动机。** 只有公式没有解释 = 没读懂。

```latex
\begin{equation}
	\min \sum_{k=1}^{K} \sum_{i} \|F[i] - g_k\|_2 \cdot \mathbb{I}\{y[i] = k\}
\end{equation}
```

对应文字：

> **符号**：$F[i]\in\mathbb{R}^{d}$ 为第 $i$ 个像素的特征，$g_k\in\mathbb{R}^{d}$ 为第 $k$ 类锚点，
> $K$ 为类别数，$\mathbb{I}\{\cdot\}$ 为指示函数。
> **原理**：把同类像素拉向自己的锚点，得到一组有代表性的类中心；
> 之所以用聚类而不是取全类均值，是因为单中心无法表达类内多样性（如背景里的多个器官）。

书写规则（与归档转换直接相关）：

- 数学内容一律用 LaTeX：写 `$V_m$`，不写 `Vm`、不写 Unicode 下标 `Vₘ`。
- 禁止在数学环境里写中文。要写文字用 `\text{english}`。原因：归档后 Obsidian 用 MathJax 渲染，
  中文混在 `$…$` 里会渲染异常（`docs/05-LaTeX转Obsidian规范.md` 有详解）。
- 多行公式用 `equation` / `align` 环境即可，脚本会自动转成 Obsidian 兼容的写法；
  但**不要用 `\substack`、`\binom`、`\boldsymbol` 这类扩展命令**，转换后会出问题。
- 公式编号：脚本把 `\tag{N}`、`\eqno` 统一转成行尾的 `\qquad (N)`，所以编号写法随意。

### 6. 实验数据与评估指标

- **数据集**：名称、模态、规模、划分方式，以及「为什么用这个数据集」。
- **指标**：定义 + 取值范围 + 越大越好还是越小越好。
- 只留下真正参与了结论的指标，不要把表格里所有列抄一遍。

### 7. 实验结果

三段式：**主实验 → 消融 → 可视化/案例**。

- 主实验：和谁比、差多少（写具体数字）、**为什么会有这个差距**。
- 消融：哪个模块贡献最大、去掉它掉多少。这一段最能体现你是否读懂了模块分工。
- 可视化：用图说明「模型错在哪」，比再列一行数字有用。

> 数字要抄全（含标准差），但结论必须落到「说明了什么」。只抄表格等于没读。

### 8. 作者工作评价

站在作者视角写：优点、作者自己承认的局限、作者提出的 future work。
这一节不入卡片，但汇报时「这篇的坑在哪」就从这里来。

### 9. 自己对该论文的评价（最有价值的一节）

三段，缺一不可：

| 段 | 写法 | 反例 |
| --- | --- | --- |
| 优点 | 具体到设计，不说「创新性强」 | 泛泛夸奖 |
| 缺点 | 指出**可验证**的弱点（假设过强、某模块对某类数据无效、指标缺校准） | 只写「数据集小」 |
| 可改进方案 | 5 步落地模板（见下） | 只写「可以加注意力」 |

**可改进方案的五步模板**（这是唯一能直接变成你自己工作的部分）：

1. **改哪个模块**：指明原方法的哪个环节、哪条公式。
2. **改成什么**：给出新的模块/项，说清输入输出。
3. **为什么能解决**：把「缺点」和这个改动一一对应，不要跳步。
4. **写成公式**：新公式 + 符号说明 + 原理，不要只说想法。
5. **预期收益与验证方式**：预期提升哪项指标、准备在哪个数据集/合成实验上验证。

> [!tip] 汇报加分项
> 自评里如果已经把公式写出来了，汇报的最后三分钟几乎不需要准备——照读即可，
> 而且听众能立刻判断「这个想法成不成立」。

## 三、图表

- 所有图片放 `pic/`，命名 `screenshot001`、`screenshot002`… 递增。
- 用 `\begin{figure}[H]` 就地放置，避免图片飘到文末。
- 表格用 `booktabs` 三线表（`\toprule` `\midrule` `\bottomrule`），不要竖线。
- 图注写「这张图在说明什么」，不写「图 1」（编号会自动生成）。
- 归档时**图与表不会进卡片**（只保留正文），所以正文里的结论必须写成不依赖图片也能读懂。

## 四、提交前自检清单

- [ ] 8 节标题没改名，节都在
- [ ] 第 2 节一段话能独立读懂，且含具体数字
- [ ] 方法一节每个模块都写了「为了解决什么」
- [ ] 每个关键公式后都有**符号**与**原理**
- [ ] 数学环境内没有中文
- [ ] 实验一节写了「为什么有差距」，不只是列数字
- [ ] 自评含可改进方案，且写到了公式级
- [ ] `xelatex document.tex` 连编两次无报错，`\cref` 正常
- [ ] 报告里没有个人信息（学号、导师姓名、联系方式、本机绝对路径）
- [ ] 元数据表里这一篇的标签已填

## 五、常见问题

**Q：一篇论文读了 3 小时还是写不出「研究问题」那一段？**
A：说明还没读懂。回到 abstract + 实验表格，只回答三个问题：它想解决什么、用什么手段、
数字是多少。三个问题的答案拼起来就是那一段。

**Q：公式太多，全都要解释吗？**
A：只解释你写进报告的「关键公式」（通常是 2~5 个：主损失、核心模块的作用、创新点）。
基础铺垫里的通用公式（如 softmax）一句话带过即可。

**Q：报告要多长？**
A：方法类论文 6~12 页（含图）比较合适。少于 5 页通常意味着模块分工没写；超过 15 页往往是抄了太多背景。

**Q：能不能直接贴论文原文的段落？**
A：不能。报告的价值在于「你重述了什么」。抄原文的段落半年后自己都读不进去，
而且归档后卡片会变成论文摘要的拼接，失去检索价值。
