# 论文卡片与标签体系

## 一、卡片是什么

**一张卡片 = 一篇论文的全部可检索信息。** 卡片不是报告的副本，而是报告的「可检索视图」：
正文五节对应报告的五节，前面的属性（frontmatter）和标签是给检索用的。

卡片**由脚本生成**，不要手改。要改内容 → 改 LaTeX 报告或元数据表 → 重跑脚本。

## 二、卡片长什么样

```markdown
---
论文题目: "EviPrompt: A Training-Free Evidential Prompt Generation Method ..."
期刊会议: "IEEE Transactions on Image Processing"
年份: 2024
文献类型: "期刊"
分区: "1区"
影响因子: "15.3"
研究内容: "医学图像分割"
批次: 3
报告时间: 2026-01-28
tags:
  - 调研汇报论文库
  - 研究论文/论文卡片
  - 种类/医学图像分割
  - 挑战/通用基础模型与上下文学习
  - 挑战/不确定性建模
  - 技术/提示学习与上下文学习
  - 技术/不确定性建模
---

# SAM免训练证据提示-EviPrompt

> [!info] 文献来源
> Y. Xu, J. Tang, A. Men and Q. Chen, "EviPrompt: ...", in IEEE TIP, vol. 33, pp. 6204-6215, 2024, doi: 10.1109/TIP.2024.3482175.

## 研究问题          ← 报告第 2 节
## 研究动机          ← 报告第 3 节
## 方法要点          ← 报告第 4 节
## 实验结果与指标    ← 报告第 6 + 5 节
## 自评（优点、缺点、可改进方案）  ← 报告第 8 节
## 同类论文          ← Dataview 自动查询
## 附件与出处        ← 链接到 PDF 与报告源目录
```

## 三、属性字段表

| 字段 | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `论文题目` | 字符串 | 元数据表 | 完整英文题目，用于表格展示 |
| `期刊会议` | 字符串 | 元数据表 | 全称（可带缩写） |
| `年份` | 数字 | 元数据表 | 发表年份，用于排序 |
| `文献类型` | 字符串 | 元数据表 | `期刊` / `会议`；留空则按分区是否含 `CCF` 自动判定 |
| `分区` | 字符串 | 元数据表 | 期刊填分区（`1区`/`2区`），会议填等级（`CCF A`）。字段名可自定义，意义保持一致即可 |
| `影响因子` | 字符串 | 元数据表 | 期刊影响因子；会议留空 |
| `研究内容` | 字符串 | 自己写 | 一句话，用于统计表；**不是标签**，只作展示 |
| `批次` | 数字 | 元数据表 | 第几次调研，用于分组与排序 |
| `报告时间` | 日期 | 元数据表 | 汇报日期 |
| `tags` | 列表 | 元数据表 | 三轴标签 + 两个固定库标签 |

> [!important] 字段分工原则：**关键词只存一处**
> 标签（关键词）**只写在 `tags` 里**，不要再往属性里塞一遍。
> 同一件事写两个地方，早晚会不一致，检索时就会漏。
> 属性只放**标量**（题目、年份、分区这类摘抄信息）。

## 四、三轴标签体系

这是整套范式最关键的设计。三轴各回答一个问题，合起来给出三个检索入口：

| 轴 | 回答 | 例子 | 每篇数量 |
| --- | --- | --- | --- |
| `种类/…` | 做的是**哪类任务** | `种类/医学图像分割` | 1（最多 2） |
| `挑战/…` | 这篇主攻**哪个难点** | `挑战/不确定性建模` | 2~3 |
| `技术/…` | 实际用了**什么技术** | `技术/提示学习与上下文学习` | 1~4 |

词表是**闭集**，见 `obsidian/标签词表.md`（人读的判定要点）与 `tools/taxonomy.csv`
（脚本读取的顺序与校验来源）。**新增标签必须先改这两个文件**，否则会出现
`多模态融合` / `多模态` / `跨模态融合` 三种写法并存的局面。

### 为什么不用一个标签了事

一维标签只能回答「这是哪一类任务」，而文献调研真正要问的是：

- 「所有用**不确定性建模**去解**半监督分割**的论文有哪些？」→ 需要同时筛 `技术/` 和 `种类/`
- 「**多模态融合**这个难点在**诊断**和**分割**两个任务上分别怎么解？」→ 需要 `挑战/` 交叉 `种类/`
- 「**图神经网络**都被用在哪些任务上，还剩哪些任务没人用？」→ `技术/` 交叉 `种类/`，空白即机会

三轴 + Dataview 让这些问题的答案是「点一下」，而不是「翻 30 篇笔记」。

### 标签怎么定（实操顺序）

1. 报告写完后，回看**第 2 节（研究问题）**定 `种类/`：它输出的是什么？类别？掩码？变换？
2. 回看**第 3 节（研究动机）**定 `挑战/`：作者列的 gap 里，本文真正攻的是哪几个？
   注意只选**本文主攻**的，不是「顺带也解决了」的。
3. 回看**第 4 节（方法要点）**定 `技术/`：实际用了哪些模块/损失/训练策略。
4. 定完后看一眼分类表：自己出现在预期的分组里吗？如果出现在三个不相干的分组，
   说明标签选得太泛，回去删。

## 五、同类论文查询（卡片里的 Dataview）

```dataview
TABLE 分区 AS 分区, 年份 AS 年份, 研究内容 AS 研究内容
FROM "论文卡片"
WHERE file.name != this.file.name AND
  length(filter(file.etags, (t) => contains(this.file.etags, t)
    AND (startswith(t, "#种类/") OR startswith(t, "#挑战/") OR startswith(t, "#技术/")))) > 0
SORT 批次 ASC
```

逐句解释：

- `file.etags`：当前文件被 Obsidian 索引出的全部标签（含嵌套标签的完整路径，如 `#种类/医学图像分割`）。
- `contains(this.file.etags, t)`：这一句的 `this` 指**当前卡片**，即「本卡片的标签集合里有没有标签 `t`」。
- `startswith(t, "#种类/")` 等：只在三轴标签范围内比较，避免被 `调研汇报论文库` 这种库标签带偏。
- `length(...) > 0`：只要有**任意一个**三轴标签相同，就算同类。
- `SORT 批次 ASC`：按调研顺序排，能看出「我是什么时候开始注意这个方向的」。

> 如果没有任何结果，说明这篇的标签太独特——先检查词表，而不是立刻加新标签。

## 六、命名规范

| 对象 | 规范 | 例子 |
| --- | --- | --- |
| 报告目录 | `<批次:两位>-<序号>` | `03-1` |
| 报告源文件 | `document.tex` | 固定名，脚本靠它定位 |
| 报告图片 | `pic/screenshot<三位递增>.png` | `pic/screenshot004.png` |
| 卡片标题（H1） | `<短标题>`：任务-方法-代号 | `SAM免训练证据提示-EviPrompt` |
| 卡片文件名 | `<批次:两位>-<序号> <短标题>.md` | `03-1 SAM免训练证据提示-EviPrompt.md` |
| 附件（原文） | `<批次:两位>-<序号>-论文原文.pdf` | `03-1-论文原文.pdf` |
| 附件（报告） | `<批次:两位>-<序号>-阅读报告.pdf` | `03-1-阅读报告.pdf` |

「短标题」的写法：**先说你一眼能找到的线索，再放方法代号**。
`稠密Transformer基础模型MoE-脑影像多任务` 比 `Denseformer-moe` 好——
半年后你记得的是「那个 MoE 做脑影像多任务的」，不是论文的原名。
